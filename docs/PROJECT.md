# 项目定义

## 项目背景

本仓库是 `chillibasket/walle-replica` 的个人 Fork，本地 `origin` 指向 `BruceZhang111/walle-replica`。上游项目提供 Arduino 运动控制固件、舵机校准程序，以及运行在 Raspberry Pi 上的 Flask 网页控制系统。本项目当前处于可行性、资料整理和采购准备阶段。

## 最终目标

制作并长期维护一台可稳定演示和作为生日礼物交付的 WALL-E 实体机器人。第一阶段复现原项目能力，后续在不破坏底层安全控制的前提下评估语音识别和语言模型对话。

## 要解决的问题

- 获取并验证完整 STL/STEP 模型、打印清单和必要改进件。
- 确定控制器、电机、舵机、电源、音频、摄像头和紧固耗材的兼容规格。
- 在 Arduino Uno 上可靠控制两台履带电机和七个舵机。
- 在 Raspberry Pi 上提供网页、游戏手柄、声音、TTS、相机和 Blockly 控制。
- 完成供电隔离、共地、低电压保护、线束管理和可维修装配。
- 建立分阶段验证流程，避免在整机装配后才发现尺寸、电源或控制问题。

## 预期交付物

- 可装配的3D打印件、打印记录和必要的模型改动记录。
- 完整 BOM、采购记录、接线图和电源预算。
- 可编译的 Arduino 主固件与校准固件。
- 可部署的 Raspberry Pi Web 服务及本地配置说明。
- 可用游戏手柄操控、播放 WAV 音频并执行预设/随机动作的实体机器人。
- 台架、子系统和整机验证记录，以及持续维护文档。

## 当前范围

代码中已经存在并计划复现的能力：

- 两路履带电机开环速度与转向控制。
- 七路舵机标定、平滑速度/加速度控制、动作队列和随机自主动作。
- Arduino 与 Raspberry Pi 之间的 USB 串口通信（115200 baud）。
- Flask 网页、虚拟摇杆、浏览器 Gamepad API、手动舵机控制。
- WAV 音效播放、英文 TTS、Blockly 动作、可选电池检测、OLED和 CSI 相机流。

当前计划中的核心硬件包括 Arduino Uno R3、Arduino Motor Shield Rev3 兼容板、PCA9685、Raspberry Pi 4B、七个 MG90S 级舵机和两台 12V/37mm/100–150RPM 偏心轴减速电机。具体品牌、供应商和电流规格均待采购前确认。

## 暂不处理

- SLAM、自主导航、视觉跟随、复杂避障和电机编码器闭环。
- 在 Arduino Uno 上引入 FreeRTOS。
- 完全离线的大语言模型推理。
- 在基础行走、舵机和供电未稳定前开发连续唤醒与自由对话。
- 为追求外观而提前修改所有3D模型；先验证关键安装尺寸和运动机构。

## 技术路线

```text
浏览器/游戏手柄
       │ Wi-Fi / HTTP
       ▼
Raspberry Pi 4B
Python + Flask + 音频 + Picamera2
       │ USB 串口
       ▼
Arduino Uno R3
       ├── Motor Shield Rev3 → 两台12V履带电机
       └── I²C PCA9685      → 七个舵机
```

- Arduino 使用现有非阻塞主循环、动作队列和串口协议，不依赖 RTOS。
- Raspberry Pi 使用 Linux/systemd 运行 Python 服务；硬件差异写入 `local_config.py`。
- 机械文件优先直接打印 STL；需要改孔位或支架时使用 Fusion 导入 STEP。STEP 可编辑为实体，但不包含原 SolidWorks 特征历史；STL 仅作为网格处理。
- 语言模型扩展采用“语音识别 → LLM → 白名单动作解析 → Arduino”的安全边界，模型不得直接生成任意电机串口命令。

## 最终验收标准

- 冷启动后系统能稳定进入可控制状态，无需临时接线或手工修复。
- 手柄能够完成前进、后退、左右转和停止，失联或异常时能够停止。
- 七个舵机完成逐机校准，无持续堵转、明显机械干涉或越限。
- 能执行至少三个可重复动作，并能播放已下载的 WAV 音乐/音效。
- 连续运行至少30分钟不出现树莓派掉电重启、驱动过热、导线异常发热或结构脱落。
- 电池具有保险、总开关、低压监测/报警及安全充电方案。
- 代码、接线、BOM、校准值和验证结果已记录，Git 工作区不存在意外修改或敏感信息。
